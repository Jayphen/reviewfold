JAY-5 · Slice 1

Document creation, end to end

The smallest production-shaped slice: a user enters a title and Markdown/plain text, the server validates it, and MongoDB atomically persists a document plus immutable revision 1.

User experience

  1. Open /documents/new
  2. Enter title and content
  3. Choose “Create document”
  4. Redirect to /documents/$documentId

Atomicity: use a MongoDB transaction so a document can never exist without revision 1. Development therefore needs a replica set.

Implementation sequence

1

Foundation

  • Scaffold TanStack Start with React 19 and TypeScript.
  • Add Astryx, MongoDB driver, runtime schema validation, and test tooling.
  • Create environment validation and a cached server-only Mongo client.
  • Run MongoDB as a local replica set.
2

Contracts and domain

  • Define CreateDocumentCommand and DocumentCreated.
  • Generate IDs in the application layer.
  • Set revision to 1 and status to draft server-side.
  • Never accept owner, status, revision number, or timestamps from the browser.
3

Persistence operation

  • Insert bounded current state into documents.
  • Insert full immutable content into document_revisions.
  • Create unique index on { documentId: 1, revision: 1 }.
  • Translate duplicate/transient failures into typed application errors.
4

UI and server boundary

  • Build the route using Astryx fields, textarea, alert, and button primitives.
  • Call a POST createServerFn with validated data.
  • Disable duplicate submission and preserve entered values on failure.
  • Redirect only after committed persistence.
5

Read-back page

  • Add the minimum detail route needed to prove creation.
  • Load document plus current revision through a query service.
  • Render title, content, “Draft,” and “Revision 1.”
  • No edit controls in this slice.
6

Verification

  • Unit-test validation and application invariants.
  • Integration-test transactional persistence against MongoDB.
  • Browser-test success, invalid input, and retry after server failure.
  • Run accessibility checks for labels, errors, focus, and pending state.

Definition of done

  • ✓ Valid input creates exactly one document and revision 1.
  • ✓ Revision content is not duplicated into current document state.
  • ✓ Failed writes leave neither partial record.
  • ✓ Invalid input never reaches persistence.
  • ✓ Success opens a read-back view of committed data.
  • ✓ Keyboard and screen-reader errors are understandable.
  • ✓ UI has no imports from server/.

Risks and deliberate cuts

Identity: if auth is not part of the first slice, use one explicit development actor behind a replaceable ActorProvider; do not trust an owner ID from the form.
Content limits: choose a conservative request/document limit now and test the boundary.

Not included: library/search, revision 2, autosave, review requests, anchored comments, rubrics, realtime, diffing, notifications, or rich text.

Assumption: the repository is empty, so this is a greenfield proposal. TanStack Start guidance was checked against current docs: validated POST server functions and redirects are supported. Design fallback: DaisyUI/Tailwind because Reviewfold has no design system files yet; production UI should use Astryx.
