03 / paths

{ outcome: 'created', documentId }

PostgreSQL committed both rows. The handler returns the document ID.

  1. Zod returns a normalized CreateDocumentCommand.
  2. Application adds trusted actorId and workspaceId.
  3. Persistence generates document and revision UUIDs.
  4. Transaction inserts both rows and commits deferred constraints.
  5. Handler consumes Ok with .match().

{ outcome: 'invalid', issues }

The handler returns validation issues before it asks for context or calls persistence.

  1. Handler receives input as unknown.
  2. Zod rejects command ID, title, content, or extra fields.
  3. Issue mapping copies the field and message into the contract type.
  4. Handler returns without creating a ResultAsync.

already-committed → created

The browser gets created with the ID from the first successful command.

  1. Repository attempts the transaction without a preflight read.
  2. Unique constraint rejects the repeated workspace and command ID.
  3. Transaction helper rolls back the failed transaction.
  4. Conflict recovery looks up the original document ID.
  5. Application maps both persistence outcomes to the same created result.

{ outcome: 'recoverable-failure', message }

The application supports this result, but the default create repository does not emit it.

  1. Application type accepts persistence-unavailable from a persistence operation.
  2. Application maps it to document-creation-unavailable.
  3. Handler returns a fixed message and omits driver details.
  4. Default repository attempts a write first, so known failures are ambiguous instead.

{ outcome: 'ambiguous', message }

A write failed and the code cannot prove whether PostgreSQL committed. A retry must reuse the command ID.

  1. Repository catches a known PostgreSQL or network failure during the write.
  2. Persistence emits persistence-outcome-ambiguous.
  3. Application maps it to document-creation-outcome-ambiguous.
  4. Handler returns a fixed message that tells the caller to reuse the command ID.

Expected errors versus exceptions

The code uses ResultAsync for known database failures. Unknown driver errors and impossible states still throw.

04 / taxonomy
Condition Representation Boundary behavior
Invalid browser command Portable result The handler returns invalid and does not call persistence.
Workspace command already committed ResultAsync Ok The application returns created with the original document ID.
Injected persistence-unavailable error Supported mapping The application can map it, but the default create repository does not emit it.
Recoverable failure during write ResultAsync Err The handler returns ambiguous. A retry uses the same command ID.
Unknown driver error or impossible state Exception The mapper throws the original error.

Rows written by one transaction

One checked-out PostgreSQL client inserts the document and revision 1. PostgreSQL checks the deferred foreign key during COMMIT.
